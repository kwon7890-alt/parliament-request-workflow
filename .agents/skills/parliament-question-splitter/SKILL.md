# 국회 자료요구서 문항목록 만들기

## 언제 쓰는지

- 프로젝트의 `원문/` 폴더에 있는 국회 자료요구서 PDF를 문항 단위 CSV로 바꿀 때 사용한다.
- 결과를 만드는 실행 파일 `split.py`가 프로젝트 맨 위에 필요할 때 사용한다.
- 사용자가 정답 또는 교체본 `문항목록.csv`를 제공하면 그 파일을 출력 기준으로 삼는다.

## 입력과 결과

- 입력: `원문/*.pdf`
- 실행 파일: 프로젝트 맨 위의 `split.py`
- 결과: `data/문항목록.csv`
- 열 순서: `파일명 | 위원회 | 의원 | 제출기한 | 문항번호 | 요구내용 | 세부항목 | 비고`
- 인코딩: UTF-8-SIG
- 사용 라이브러리: `pypdf`와 파이썬 표준 라이브러리만 사용한다.

## 순서

1. 작업 전 기존 `split.py`, 원문 PDF, 사용자가 제공한 정답 CSV를 읽는다. 정답 CSV는 참고만 하고 원문을 수정하지 않는다.
2. `pypdf`를 불러올 수 있는지 확인한다. 없으면 설치 명령만 보여주고 사용자의 허락을 받은 뒤 설치한다.
3. 이 스킬의 [검증된 split.py](assets/split.py)를 프로젝트 맨 위에 복사한다. 기존 `split.py`가 있으면 먼저 내용을 비교하고, 사용자의 관련 로직은 보존하면서 필요한 분리·출력 규칙만 반영한다.
4. `split.py`를 실행해 `data/문항목록.csv`를 만든다.
5. 파일별 문항 수, 마지막 번호, 번호 연속 여부, 중복 키, 누락 필드를 확인한다.
6. 정답 CSV가 있으면 열 순서와 모든 셀을 문자열 그대로 비교한다. 차이가 있으면 파일명·문항번호·필드·정답 값·생성 값을 표시하고 원인을 고친 뒤 다시 실행한다.
7. 결과 화면에는 원문 PDF, 생성된 `split.py`, 생성 CSV, 검증 결과 MD를 클릭 가능한 링크로 제시한다.

## 분리 규칙

1. 첫 번째 비어 있지 않은 줄의 `○○위원회 ○○ 의원실 자료요구서`에서 위원회와 의원을 추출한다.
2. `제출기한:` 뒤의 `YYYY. M. D.`를 `YYYY-MM-DD`로 저장한다.
3. `수신:`, `담당 보좌관:`, `끝.` 줄은 저장하지 않는다. 이름·전화번호·이메일 등 연락처를 문항 데이터에 넣지 않는다.
4. 줄 맨 앞의 `숫자.`는 새 문항이다.
5. `가.`, `나.` 등 한글 순번 줄은 현재 문항의 세부항목이다. 여러 세부항목은 한 셀에서 정확히 ` / `로 연결한다.
6. `※` 줄은 현재 문항의 비고다. CSV에는 맨 앞의 `※`와 뒤 공백을 제거한 내용만 저장한다.
7. 그 밖의 줄은 바로 앞의 요구내용·세부항목·비고에 공백 하나로 이어 붙인다.
8. 파일명의 `_N문항.pdf`에서 기대 문항 수를 읽고 실제 개수·마지막 번호·1부터의 연속성을 모두 확인한다.

## 끝나는 조건

- 모든 PDF에서 기대 문항 수, 추출 문항 수, 마지막 번호가 같고 번호가 연속이다.
- `(파일명, 문항번호)`가 중복되지 않는다.
- 출력 열과 순서가 지정된 8개 열과 같다.
- 정답 CSV가 제공된 경우 행 수, 행 순서, 열 순서, 모든 셀의 차이가 0건이다.
- 원문 PDF와 정답 CSV는 변경되지 않았다.
- 생성 파일과 근거 파일을 사용자가 클릭해 검증할 수 있다.

## 하지 말 것

- 정답 CSV의 행을 코드에 직접 넣어 결과를 위조하지 않는다.
- PDF 원문, 정답 CSV 또는 `data/`의 다른 파일을 수정하지 않는다.
- 연락처나 담당 보좌관 정보를 저장하거나 검증 보고서에 노출하지 않는다.
- 문항 수가 맞지 않거나 번호가 끊겼는데 CSV를 정상 결과로 확정하지 않는다.
- 정답과 차이가 남아 있는데 단순 표기 차이라고 임의로 통과시키지 않는다.
