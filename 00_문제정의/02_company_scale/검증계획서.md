# 검증계획서: 국회 요구자료 대응 도우미 회사용 확장

> 버전: `02_company_scale`  
> 대상: 회사 자료 약 11GB, 최대 약 20GB 예상  
> 원칙: 보안·정확성·복구를 먼저 검증하고 성능 숫자는 실제 환경 측정 후 확정한다.

## 1. 사전 조건

- 자료 반입, 사용자 권한, 보존기간, 폐기, 백업 위치를 보안 담당자와 확정한다.
- 원본은 읽기 전용 보관소에 두고 시험본으로 검증한다.
- 비밀정보나 개인정보가 포함된 원문을 외부 AI 서비스로 보내지 않는다.
- 실행파일과 스크립트는 실행하지 않는다.
- C1에서 국회 업무 핵심, 공유 업무, 목록 관리, 제외·위험의 분류 기준과 공용 수집층 사용 여부를 승인한다.

## 2. 검증 영역과 합격 기준

| 번호 | 영역 | 통과 기준 |
|---|---|---|
| C-01 | 목록·분류 완전성 | 조사 대상의 파일 수·총용량·경로·크기·수정일·해시와 A~D 수집 분류 기록 |
| C-02 | 중복 | 동일 해시 파일을 중복으로 식별하고 원본 위치 모두 보존 |
| C-03 | 증분 처리 | 변경되지 않은 파일 재추출 0건, 신규·변경 파일만 처리 |
| C-04 | 원본 보호 | 수집·추출·색인 과정의 원본 변경 0건 |
| C-05 | 위험 파일 | EXE·BAT·REG 실행 0건, 모두 위험 표시·해시 기록 |
| C-06 | 압축 안전 | 정상 ZIP은 중첩 2단계까지 처리하고, 암호·손상 또는 승인 한도 초과 시 자동 중단·검토 전환 |
| C-07a | 민감정보 탐지 | 위치를 아는 가상 API 키·전화번호·이메일·IP 표본을 각각 전부 탐지(탐지율 100%) |
| C-07b | 민감정보 차단 | 비승인 민감정보의 검색 노출·임베딩 0건 |
| C-08 | 출처 | 검색·추천 결과의 원본 파일과 페이지·시트·문단 연결 100% |
| C-09 | 권한 | 권한 없는 원문·검색 결과 노출 0건 |
| C-10 | 감사 | 조회·변경·삭제·권한·색인 전환 이력 누락 0건 |
| C-11 | 복구 | 백업본에서 메타데이터와 색인을 복원하고 원본 연결 확인 |
| C-12 | 추천 | 사람이 정답화한 실제 회사 문항 표본에서 1순위 75% 이상 |
| C-13 | 수집 범위 | C·D 분류 자료가 승인 없이 내용 색인된 건 0건 |
| C-14 | HWP | C2에서 HWP 비율 측정, C4 전 처리 방식 확정, 표본 추출·출처 연결 검증 |
| C-15 | 모델·서버 이전 | 모델 메타데이터 기록, 변경 시 재임베딩, 새 색인 검증 후 전환·복귀 가능 |
| C-16 | 보존·파기 | 감사 이력에 개인정보 원문 값 0건, 만료 자료의 승인된 파기·익명화와 파기 사실 기록 |

## 3. 표본 설계

| 표본 | 선정 방법 | 확인 항목 |
|---|---|---|
| 파일 형식 표본 | PDF, HWP/HWPX, DOCX, XLSX/CSV, HTML, TXT, ZIP별 정상·오류 파일 | 추출 성공, 구조, 출처 위치 |
| 중복 표본 | 이름이 다르고 내용이 같은 파일, 내용이 다르고 이름이 같은 파일 | 해시·버전 판단 |
| 민감정보 표본 | 위치를 아는 가상 API 키·전화번호·이메일·IP를 유형별로 심은 표본 | 유형별 탐지율 100%, 차단, 승인 이력 |
| 권한 표본 | 총괄·현업·관리자 역할 | 검색·원문 접근 제한 |
| 배분 표본 | 실제 회사 문항을 담당자가 정답화 | 1순위 정확도, 근거 적절성 |
| 장애 표본 | 추출 실패, 손상 ZIP, 색인 실패, DB 중단 | 재처리·복구·이력 |
| 수집 범위 표본 | 국회 자료, 예산 자료, 설치 매뉴얼, 교육자료, 과업지시서, 실행파일 | A~D 분류와 색인 허용 여부 |
| 이전 표본 | L40S에서 RTX PRO 6000으로 옮기거나 임베딩 모델을 변경하기 전후의 동일 질의 | 모델 메타데이터, 재현성, 필요 시 재임베딩, 결과 비교, 복귀 |

실제 회사 문항 표본 수는 자료 조사 후 확정한다. PoC의 40건을 회사용 정확도 증거로 재사용하지 않는다.

## 4. 성능 측정

현재는 파일 수, 압축 해제 후 용량, 형식 비율, OCR 필요 페이지 수, 장비 사양이 확인되지 않았으므로 처리시간 목표를 추정하지 않는다. C2 조사에서 기준선을 얻은 뒤 아래 항목의 목표를 확정한다.

| 측정 항목 | 기록 값 |
|---|---|
| 최초 목록화 | 총 파일 수, 총용량, 소요시간, 실패 수 |
| 최초 추출 | 형식별 파일·페이지 수, 소요시간, 실패율 |
| 증분 갱신 | 신규·변경 파일 수, 전체 대비 재처리 비율, 소요시간 |
| 검색 | 키워드·필터·의미 검색 응답시간 분포 |
| 임베딩 | 대상 조각 수, 처리시간, 저장공간 |
| 복구 | 백업 시점, 복원시간, 누락 여부 |
| HWP | 전체 대비 파일 수·용량 비율, 변환·추출 성공률, 실패 유형 |

## 5. 보안 실패 시 중단 조건

다음 중 하나라도 발생하면 운영 전환을 중단한다.

- 원본이 변경되거나 삭제됨
- 위험 파일이 실행됨
- 비승인 민감정보가 검색·임베딩·로그에 노출됨
- 권한 없는 사용자가 원문을 열람함
- 검색 결과에서 원문 출처를 확인할 수 없음
- 감사 이력이 빠지거나 임의 수정 가능함
- 개인정보 원문 값이 감사 이력에 저장됨
- 국회 업무 무관 자료가 분류 승인 없이 내용 색인됨

## 6. 단계별 판정

| 관문 | 통과 조건 |
|---|---|
| G1 자료 반입 | A~D 분류, 공용 수집층 여부, 보안·권한·보존·파기 기준 승인 |
| G2 수집 | C-01~C-06, C-13~C-14 통과 |
| G3 검색 | C-07a~C-09 통과 |
| G4 운영 | C-10~C-11, C-15~C-16 통과 |
| G5 업무 적용 | C-12와 사용자 시나리오 통과 |

모든 관문을 통과한 뒤에만 실제 업무 자료를 대상으로 운영한다. 회사용 결과는 PoC 성공과 별개로 판정한다.
