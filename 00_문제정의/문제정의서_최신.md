# 문제정의서: 국회 요구자료 대응 도우미

## 1. 배경

A부 국회 업무 담당자는 국정감사, 상임위원회, 예산결산특별위원회, 서면질의 등으로 들어오는 자료요구를 문항 단위로 접수하고, 소관 과를 배분하고, 부서 회신을 취합한 뒤 제출 전 누락과 오류를 점검한다.

교육용 PoC 자료에서는 2026년 국정감사 요구자료 접수대장 520건을 기준으로 한다. 접수대장에는 접수번호, 접수일, 국회구분, 위원회, 요구의원, 요구유형, 문항번호, 요구내용, 요구기간, 제출기한, 제출형식, 배분구분, 배분과, 처리상태 등 15개 항목이 있다.

지금까지 대화에서 확인한 실제 확장 전제는 다르다. 회사에 가져갈 자료는 약 11GB이고, ZIP 포함 시 약 20GB까지 커질 수 있다. 따라서 이 업무 도구는 교육용 PoC와 회사용 확장 버전을 분리해 설계해야 한다.

## 2. 현재 업무

| 구분 | 내용 |
|---|---|
| 담당자 | 국회 총괄 담당, 현업 담당(과) |
| 주요 흐름 | 접수 → 문항 분해 → 배분 후보 추천 → 배분 확정 → 부서 회신 → 취합·검사 → 확정 → 제출본 확인 |
| 총괄 담당 역할 | 요구서 접수, 문항 정리, 소관 과 배분, 이견·재배정 처리, 회신 취합, 검사, 확정 |
| 현업 담당 역할 | 자기 과 문항 확인, 회신 작성, 회신완료 처리, 재배정요청, 보완 답변 |
| 사람이 판단할 일 | 최종 배분, 주관·협조 과 결정, 개인정보 여부, 날짜·기한 이상 확인, 보완요청 여부, 확정 여부 |

## 4. 문제

| 문제 영역 | 내용 |
|---|---|
| 시간 | 요구서 PDF와 접수대장을 사람이 보며 문항별로 배분하면 시간이 많이 걸린다. 요구서 1건에 여러 문항이 들어 있어 문항 단위 처리가 필요하다. |
| 오류 | 요구기간 연도 누락, 기간 역전, 제출기한 이상, 조직도에 없는 부서명, 합계 불일치, 중복 접수, 상태값 공백 차이 같은 오류가 생길 수 있다. |
| 판단 차이 | 한 문항이 여러 과에 걸치거나 배분기준표 키워드가 없으면 담당자마다 판단이 달라진다. |
| 이력 단절 | 재배정, 보완요청, 확인필요 사유를 남기지 않으면 후임자가 왜 그렇게 처리했는지 알기 어렵다. |
| 자료 분산 | 지침, 업무메일, 구두지시, 접수대장, 원문 PDF, 부서 회신 엑셀, 답변 양식, 결재 양식이 서로 다른 위치와 형식으로 존재한다. |
| 실제 자료 규모 | 회사 자료는 11~20GB까지 커질 수 있어 파일을 매번 직접 읽는 방식으로는 느리고 불안정하다. |
| 보안 | 실제 자료에는 이름, 연락처, 이메일, API 키처럼 보이는 비밀정보, 네트워크 구성, 장비 계정, 보안장비 정보가 포함될 수 있다. |
| 위험 파일 | EXE, BAT, REG, 보안메일 HTML 같은 파일은 실행하면 안 되고, 보관·분류·위험 표시 대상으로 다뤄야 한다. |

## 5. 목표

| 목표 | 기준 |
|---|---|
| 문항별 배분 후보 추천 | 요구내용, 배분기준표, 조직도를 기준으로 소관 과 후보를 제시한다. |
| 사람 판단 분리 | 자동 확정하지 않고, 확인필요 사유와 근거를 담당자에게 보여 준다. |
| 정확도 검증 | 시험 40건 기준 1순위 배분과 정확도 75% 이상을 목표로 한다. |
| 오류 점검 | 누락, 이상 날짜, 상태값 공백, 조직도 밖 부서명, 기준표 미매칭, 우선순위 동률을 확인필요로 표시한다. |
| 이력 유지 | 누가 언제 무엇을 왜 바꿨는지 남긴다. |
| 회사용 확장 | 11~20GB 원본 자료는 원본 보관소에 두고, 추출 텍스트·메타데이터·검색 색인·선택 임베딩으로 처리한다. |
| 보안 통제 | 개인정보와 비밀정보 후보는 마스킹하고 임베딩 제외 또는 별도 승인 대상으로 분리한다. |

## 6. 범위

### 만들 것

| 범위 | 내용 |
|---|---|
| PoC | 교육용 520건 자료를 읽고 문항별 상태를 만든다. |
| 배분 추천 | 배분기준표, 조직도, 요구내용 기반으로 후보 과를 추천한다. |
| 상태 관리 | `접수 → 배분확정 → 회신중 → 회신완료 → 확정` 상태를 관리한다. |
| 예외 처리 | `재배정요청`, `보완요청`, `확인필요`를 기록한다. |
| 취합·검사 | 부서 회신 엑셀을 기준으로 누락·형식·합계·연도·상태 오류를 점검한다. |
| 회사용 수집 | 원본 등록, 해시 중복 제거, 텍스트 추출, 위험 파일 분류, 민감정보 탐지, 검색 색인 생성을 설계한다. |

### 만들지 않을 것

| 제외 범위 | 이유 |
|---|---|
| 답변 문장 자동 작성 | 답변 내용의 사실관계는 현업 담당 책임이다. |
| 결재 자동 처리 | 결재는 사람과 내부 절차 영역이다. |
| 국회 제출 자동 처리 | 제출은 범위 밖이며 별도 시스템과 책임 절차가 필요하다. |
| 내부 시스템 실제 등록 | PoC와 설계 단계에서는 실제 기관 시스템 연동을 하지 않는다. |
| 전체 20GB 원본 임베딩 | 비용, 시간, 보안 통제가 어렵다. 필요한 텍스트 조각만 임베딩한다. |
| EXE/BAT/REG 실행 | 위험 파일은 실행하지 않고 분류·보관·검토 대상으로만 둔다. |

## 9. 핵심 판단

PoC는 파일 직접 읽기 방식으로 진행한다. 현재 교육용 자료 규모에서는 가장 빠르고 설명 가능하다.

회사용 `02_company_scale`은 별도 설계로 간다. 원본은 파일 보관소에 두고, DB에는 원본 경로, 해시, 추출 텍스트 위치, 상태, 이력, 권한, 검색용 메타데이터를 저장한다. 임베딩은 전체 파일이 아니라 요구내용, 지침, 조직도, 과거 유사 문항처럼 추천에 필요한 텍스트 조각에만 적용한다.
