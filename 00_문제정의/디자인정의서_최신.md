# 디자인정의서: 국회 요구자료 대응 도우미

## 1. 설계 원칙

| 원칙 | 내용 |
|---|---|
| 사람 최종 판단 | AI와 규칙은 후보와 근거를 제시하고, 최종 배분·확정은 담당자가 한다. |
| 원본 보존 | 원본 접수대장, PDF, HWP/HWPX, DOCX, ZIP 등은 직접 수정하지 않는다. |
| 이력 우선 | 배분, 재배정요청, 보완요청, 확정은 모두 누가 언제 왜 했는지 남긴다. |
| 보안 우선 | 개인정보, 연락처, 이메일, API 키, 네트워크 구성정보, 장비 계정 후보는 탐지·마스킹·제외한다. |
| PoC와 운영 분리 | 교육용 검증은 가볍게, 회사용 20GB 자료는 별도 구조로 설계한다. |
| 설명 가능한 추천 | 벡터 유사도만 보여 주지 않고 키워드, 기준표, 조직도, 과거 사례 근거를 함께 보여 준다. |

## 2. 전체 버전 구조

```text
01_poc/
  data/
  cases.json
  app/
  server/

02_company_scale/
  raw_vault/
  extracted/
  metadata_db/
  search_index/
  vector_index/
  app/
  server/
  logs/
```

| 버전 | 목적 | 주요 저장소 |
|---|---|---|
| `01_poc` | 520건 교육용 자료로 기능 검증 | CSV, XLSX, PDF, `cases.json` |
| `02_company_scale` | 회사 자료 11~20GB 처리 | 원본 보관소, 메타데이터 DB, 검색 인덱스, 벡터 인덱스 |

## 3. 업무 흐름

| 단계 | 총괄 담당 | 현업 담당 | 시스템 처리 | 사람 확인 지점 |
|---|---|---|---|---|
| 접수 | 요구서와 접수대장 확인 | 해당 없음 | 원본 접수대장 또는 PDF에서 기본 항목 추출 | 날짜·기한 이상, 중복 접수 |
| 분해 | 요구서를 문항 단위로 확정 | 해당 없음 | 문항 후보 추출, 하위 항목 묶음 표시 | 하위 항목을 별도 문항으로 볼지 여부 |
| 배분 추천 | 추천 후보 검토 | 해당 없음 | 기준표·조직도·과거 사례 기반 후보 3순위 제시 | 최종 소관 과 확정 |
| 배분 확정 | 주관 과와 협조 과 지정 | 배분 결과 확인 | 상태를 `배분확정`으로 변경, 이력 기록 | 여러 과 관련 문항의 주관 과 |
| 회신 | 현황 확인 | 답변과 근거 입력 | 상태를 `회신중` 또는 `회신완료`로 변경 | 답변 사실관계와 근거 |
| 재배정요청 | 요청 검토 후 반영 또는 반려 | 우리 과 아님 사유 입력 | 상태를 `재배정요청`으로 변경 | 재배정 수용 여부 |
| 검사 | 누락·오류 점검 | 보완 답변 | 규칙 검사와 확인필요 목록 생성 | 보완요청 여부 |
| 확정 | 최종 확정 | 필요 시 최종 보완 | 상태를 `확정`으로 변경 | 제출본 포함 여부 |
| 제출본 | 결재·제출 별도 진행 | 해당 없음 | 확정 목록과 미확정 사유 표시 | 결재와 제출은 범위 밖 |

## 4. 상태 설계

기본 상태 흐름:

```text
접수 → 배분확정 → 회신중 → 회신완료 → 확정
```

예외 상태:

```text
재배정요청
보완요청
확인필요
```

| 상태 | 의미 | 다음 상태 |
|---|---|---|
| 접수 | 문항이 등록되었으나 배분 확정 전 | 배분확정, 확인필요 |
| 배분확정 | 총괄 담당이 주관 과를 정함 | 회신중, 재배정요청 |
| 회신중 | 현업 담당이 회신 작업 중 | 회신완료, 재배정요청 |
| 회신완료 | 현업 담당 회신 완료 | 보완요청, 확정 |
| 재배정요청 | 현업 담당이 소관 변경 요청 | 배분확정, 확인필요 |
| 보완요청 | 총괄 담당이 보완 요청 | 회신중, 회신완료 |
| 확인필요 | 자동 확정하면 안 되는 상태 | 배분확정, 보완요청, 확정 |
| 확정 | 제출본 대상 후보로 확정 | 제출 절차는 별도 |

## 5. 화면 설계

### 5.1 시작 화면: 현황

| 항목 | 내용 |
|---|---|
| 사용자 | 국회 총괄 담당, 현업 담당 |
| 보이는 정보 | 전체 건수, 상태별 건수, 제출기한 임박, 재배정요청, 보완요청, 과별 회신 현황 |
| 버튼 | 새로고침, 상태 필터, 내 과만 보기, 상세 보기 |
| 필요한 이유 | 담당자가 오늘 처리할 일을 빠르게 정하고 병목을 확인한다. |

### 5.2 배분 화면

| 항목 | 내용 |
|---|---|
| 사용자 | 국회 총괄 담당 |
| 보이는 정보 | 접수번호, 문항번호, 요구내용, 요구기간, 제출기한, 제출형식, AI추천 후보, 추천 근거, 현재 배분과, 확인필요 사유 |
| 버튼 | AI추천, 배분확정, 확인필요 표시, 재배정 반영, 이력 보기 |
| 필요한 이유 | 후보는 시스템이 제시하지만 최종 배분은 사람이 하도록 한다. |

### 5.3 현업 회신 화면

| 항목 | 내용 |
|---|---|
| 사용자 | 현업 담당 |
| 보이는 정보 | 내 과 문항, 요구내용, 제출기한, 회신 양식 항목, 보완요청 사유, 처리 이력 |
| 버튼 | 회신 저장, 회신완료, 재배정요청, 보완 답변 저장 |
| 필요한 이유 | 현업 담당이 자기 과 문항만 보고 회신하고 이견을 남길 수 있게 한다. |

### 5.4 취합 화면

| 항목 | 내용 |
|---|---|
| 사용자 | 국회 총괄 담당 |
| 보이는 정보 | 문항별 회신 상태, 미회신 과, 보완요청 대상, 검사 결과, 확정 가능 여부, 처리 이력 |
| 버튼 | 검사 실행, 보완요청, 확정, 제출본 대상 보기, 이력 보기 |
| 필요한 이유 | 제출 전 누락·오류와 사람 판단 대상을 분리한다. |

### 5.5 회사용 수집·색인 화면

| 항목 | 내용 |
|---|---|
| 사용자 | 총괄 담당 또는 시스템 관리자 |

## 7. 회사용 파일 수집 정책

| 파일 유형 | 처리 |
|---|---|
| PDF | 텍스트 추출, 페이지 단위 색인, 연락처·이메일 마스킹 |
| HWPX | XML/미리보기 텍스트 추출, 템플릿 여부 분류 |
| HWP | 직접 처리 어려우면 변환본 우선 사용, 별도 처리 과제로 분리 |
| DOCX | 문서 XML에서 텍스트와 표 추출 |
| XLSX/CSV | 시트·컬럼·행 단위 추출 |
| HTML | 본문 텍스트 추출, 보안메일·교안·웹앱 구분 |
| TXT | 인코딩 감지 후 텍스트 추출 |
| ZIP | 목록과 해시 기록, 필요한 경우 한 번만 안전 해제 |
| EXE | 실행 금지, 파일 정보와 해시만 기록 |
| BAT/REG | 실행 금지, 위험 파일로 표시하고 내용은 검토용으로만 읽음 |

## 9. 추천 로직

| 점수 요소 | 설명 |
|---|---|
| 키워드 점수 | 요구내용이 배분기준표 키워드와 일치하는지 본다. |
| 제외어 | 제외어가 있으면 해당 규칙 점수를 낮추거나 제외한다. |
| 우선순위 | 기준표 우선순위가 높은 규칙을 우선한다. |
| 조직도 점수 | 조직도 주요업무·대표키워드와 요구내용의 관련성을 본다. |
| 공통 문항 감지 | 업무추진비, 국외출장, 관용차량, 위원회 운영 등 전 과 취합 가능성을 표시한다. |
| 과거 사례 | 유사 문항이 과거에 어느 과로 배분됐는지 참고한다. |
| 벡터 유사도 | 회사용에서는 필요한 텍스트 조각에만 적용한다. |
| 확인필요 조건 | 미매칭, 동률, 여러 과 관련, 조직도 밖 후보, 민감정보 포함 여부를 표시한다. |

## 10. 서버 API

서버는 PoC에서는 `/api/app` 하나로 시작한다. 회사용에서도 외부 API 모양은 단순하게 유지하고, 내부에서 파일 보관소·DB·검색 인덱스를 나누어 처리한다.

### GET 조회

```http
GET /api/app?view=dashboard&role=총괄
```

```json
{
  "ok": true,
  "view": "dashboard",
  "summary": {
    "total": 520,
    "접수": 120,
    "배분확정": 140,
    "회신중": 130,
    "회신완료": 90,
    "확정": 40,
    "재배정요청": 8,
    "보완요청": 12
  }
}
```

### POST 작업

지원 작업:

```text
접수
AI추천
배분
회신
재배정요청
보완요청
확정
파일등록
텍스트추출
색인생성
민감정보검토
```

예시:

```json
{
  "action": "AI추천",
  "actor": "국회 총괄 담당",
  "payload": {
    "caseId": "2026-0001-01",
    "useSemanticSearch": true
  }
}
```

응답 예시:

```json
{
  "ok": true,
  "caseId": "2026-0001-01",
  "recommendation": {
    "candidates": [
      {
        "rank": 1,
        "dept": "운영지원과",
        "reason": "업무추진비 키워드와 공통 취합 지침에 근거",
        "needsHumanReview": true
      }
    ],
    "warnings": ["공통 문항 가능성"]
  }
}
```

## 11. 화면·서버·하지 않을 것

| 구분 | 처리할 것 |
|---|---|
| 화면 | 목록, 필터, 검색, 상세 보기, 상태 버튼, 회신 입력, 재배정요청, 보완요청, 확인필요 표시 |
| 서버 | 원본 읽기, 상태 저장, 이력 기록, 추천 계산, 검사 실행, 파일 해시, 중복 제거, 텍스트 추출, 색인 생성, 민감정보 탐지 |
| 하지 않을 것 | 답변 문장 자동 작성, 결재 자동 처리, 국회 제출 자동 처리, EXE/BAT/REG 실행, 전체 20GB 임베딩, 원본 파일 직접 수정 |

## 12. 단계 연결

| 단계 | 만들 것 | 기준 |
|---|---|---|

| S7 | 취합·검사 | 누락·오류·보완요청·확정 흐름이 된다. |
| S8 | 검증 결과 | 정확도, 조직도 밖 후보, 상태 정규화, 보안 제외 기준을 확인한다. |
| 회사용 S9 | `02_company_scale` 수집기 | 원본 등록, 해시, 중복 제거, 위험 파일 분류가 된다. |
| 회사용 S10 | 검색·선택 임베딩 | 전체 원본이 아니라 필요한 조각만 색인·임베딩한다. |

## 13. 최종 권장안

먼저 `01_poc` 성격으로 교육용 데이터를 사용해 배분 추천과 취합·검사 흐름을 완성한다. 이후 회사 자료를 붙일 때는 `02_company_scale`로 별도 구성한다.

`02_company_scale`은 원본 보관소, 추출 텍스트, 메타데이터 DB, 검색 인덱스, 벡터 인덱스가 분리된 구조여야 한다. 이 구조가 11~20GB 자료, 중복 파일, 위험 파일, 민감정보, 여러 담당자의 이력 관리를 감당할 수 있다.
