# 5개 문제정의서

## 1. 국회 요구자료 접수·배분 지원 도구

| 칸 | 내용 |
|---|---|
| ① 현재 업무 | 국회 업무 총괄 담당자는 국정감사·상임위·예결위 등에서 들어오는 요구자료를 접수한 뒤 접수번호, 위원회, 의원명, 요구내용, 제출기한, 제출형식, 배분과, 처리상태를 접수대장에 등록한다. 이후 요구내용을 문항 단위로 나누고, 배분기준표·조직도·과거 처리 사례를 참고해 소관 부서를 정한다. 한 문항이 여러 과에 걸치거나 공통 문항인 경우 주관 과와 협조 과를 따로 판단한다. |
| ② 문제 | 요구내용을 보고 소관 과를 정하는 기준이 담당자 경험에 많이 의존한다. 배분기준표에 없는 표현이 나오거나 여러 과가 관련된 문항은 사람마다 판단이 달라진다. 지침, 메일, 구두지시, 인수인계서가 흩어져 있어 최신 기준을 찾는 데 시간이 걸린다. 배분 이견이나 재배정 사유가 파일·메일에 흩어지면 다음 담당자가 왜 그렇게 배분했는지 알기 어렵다. |
| ③ 목표 | 접수대장과 배분기준표, 조직도를 바탕으로 문항별 소관 과 후보와 추천 근거를 자동 제시한다. 배분 후보는 조직도에 존재하는 부서 안에서만 제시하고, 기준표 미매칭·우선순위 동률·공통 문항 가능성은 확인필요로 표시한다. 시험 문항 기준 1순위 배분과 정확도 75% 이상을 목표로 한다. 최종 배분은 사람이 확정하되, 추천 근거와 변경 이력을 남긴다. |
| ④ 범위 | 만들 것: 요구자료 접수대장 읽기, 문항별 소관 과 후보 추천, 배분기준표·조직도 기반 검증, 공통/소관 구분 보조, 확인필요 사유 표시, 배분·재배분 이력 기록. 만들지 않을 것: 답변 내용 작성, 결재, 국회 제출, 내부 행정시스템 실제 등록. 사람이 판단할 부분: 최종 배분과 확정, 주관·협조 과 결정, 기준표에 없는 신규 업무 판단, 의원실 확인이 필요한 요구내용 해석. |
| ⑤ 검증 기준 | 시험 요구문항 40건을 기준으로 1순위 배분과 정확도가 75% 이상이면 통과로 본다. 접수대장 원본의 행 수와 주요 항목은 누락 없이 유지해야 한다. 조직도에 없는 부서명을 새로 만들지 않아야 한다. 기준표 미매칭, 배분과 공란, 우선순위 동률 문항은 임의 확정하지 않고 확인필요로 표시해야 한다. 답변 품질, 결재, 실제 제출 결과는 검증 기준에 포함하지 않는다. |

## 2. 국회 요구자료 부서 회신 취합·검증 도구

| 칸 | 내용 |
|---|---|
| ① 현재 업무 | 국회 총괄 담당자는 배분이 끝난 문항을 각 부서에 보내고, 부서별 회신 파일을 받아 하나의 제출본으로 취합한다. 현업 담당자는 자기 과 소관 문항에 대해 답변 초안, 표, 근거자료를 작성해 회신한다. 총괄 담당자는 미회신 부서, 보완 필요 문항, 제출기한 임박 건을 계속 확인하고, 취합 후 누락·오류·형식 불일치를 점검한다. |
| ② 문제 | 부서별 회신 파일이 여러 개로 나뉘어 있어 최신 회신본을 찾기 어렵다. 같은 문항에 대해 일부 부서는 회신하고 일부 부서는 누락하는 경우가 생긴다. 제출기한, 회신상태, 보완요청 상태를 사람이 수작업으로 관리하므로 누락 위험이 있다. 표 합계 불일치, 기간 누락, 조직도에 없는 부서명, 형식 오류 같은 검증 항목도 담당자마다 확인 수준이 달라진다. |
| ③ 목표 | 문항별 회신 상태를 한 화면에서 관리하고, 부서 회신 파일을 취합해 누락·형식·합계 오류를 자동 점검한다. 상태는 접수, 배분확정, 회신중, 회신완료, 보완요청, 확정으로 관리한다. 미회신·기한임박·보완요청 문항을 자동 표시하고, 회신 변경 이력을 남긴다. 총괄 담당자가 제출 전 확인해야 할 항목을 정상과 확인필요로 구분한다. |
| ④ 범위 | 만들 것: 부서별 회신 파일 읽기, 문항별 회신 상태 관리, 미회신·기한임박 목록 생성, 합계·기간·부서명·필수항목 검증, 보완요청 이력 기록, 확정 대상 목록 생성. 만들지 않을 것: 답변 문장 자동 작성, 사실관계 최종 판단, 국장 결재, 국회 제출, 제출 후 수정 제출 처리. 사람이 판단할 부분: 답변 내용의 사실관계, 보완요청 여부, 제출본 확정, 비공개 정보 포함 여부. |
| ⑤ 검증 기준 | 검증용 접수대장과 부서 회신 파일을 기준으로 회신 상태가 문항별로 정확히 표시되어야 한다. 고의로 넣은 미회신, 기간 오류, 부서명 오류, 합계 불일치, 필수항목 누락을 확인필요로 검출해야 한다. 원본 접수번호와 문항번호는 중복·누락 없이 유지해야 한다. 확정되지 않은 문항을 제출본 대상으로 자동 포함하지 않아야 한다. 결재와 실제 제출 성공 여부는 검증 기준에서 제외한다. |

## 3. 예산·결산 보고서 반복 작성 지원 도구

| 칸 | 내용 |
|---|---|
| ① 현재 업무 | 예산 담당자는 매년 같은 사업 데이터(사업명, 내역사업, 세부항목, 산출근거, 연도별 예산·집행액·불용액, 전년 대비 증감, 증감사유)를 바탕으로 예산 요구안, 기재부 심의 차수본, 국회 설명자료, 확정 예산 반영자료, 결산서, 내부 검토안을 반복 작성한다. 각 단계마다 xls 자료의 숫자를 hwp 양식 표에 옮기고, 차수가 바뀔 때마다 숫자와 증감사유 문장을 수정한다. |
| ② 문제 | 같은 숫자를 xls에서 hwp로 반복 복사하면서 차수 간·문서 간 숫자 불일치가 생긴다. 천원/백만원 단위 혼동, 합계·소계 불일치, 전년도 금액 오기, 증감률 계산 오류가 발생할 수 있다. 1차, 2차, 3차, 4차 수정본이 파일명으로만 구분되어 최신본과 변경 이력을 찾기 어렵다. 양식마다 표 구조가 달라 같은 내용을 매번 다시 배치해야 한다. |
| ③ 목표 | 사업별 예산·결산 데이터를 하나의 원장으로 관리하고, 등록된 양식 템플릿에 원장 값을 넣어 xlsx·hwpx 산출물을 자동 생성한다. 원장과 산출물 간 숫자 불일치 0건, 합계·소계·증감률 자동 검산 100%, 차수별 변경 항목과 변경 사유 기록 100%를 목표로 한다. 문서 1건 작성 시간은 현재 측정값 대비 50% 이상 단축한다. |
| ④ 범위 | 만들 것: 과거 xls/hwp(hwpx) 예산·결산 문서에서 숫자·산출근거·사유 추출, 연도·차수·사업·항목 단위 원장 구축, xlsx·hwpx 템플릿 산출, 차수 간 비교표 생성, 단위 변환, 합계·증감률 검산, 변경 이력 기록, 과거 산출근거·증감사유 문장 검색. 만들지 않을 것: 예산 금액 결정, 디브레인 입력, 결재, 기재부·국회 제출. 사람이 판단할 부분: 금액 확정, 증감사유 최종 문장, 오류 여부 판단, 대외 제출 가능 범위. |
| ⑤ 검증 기준 | 과거 1개 연도의 실제 산출물 20건과 원본 xls를 시험 자료로 사용한다. 원장과 템플릿으로 20건을 재생성했을 때 숫자 셀이 원본과 100% 일치하면 통과로 본다. 일부러 넣은 숫자 오류, 합계 불일치, 단위 혼동 10건 중 10건을 확인필요로 검출해야 한다. 1차부터 4차까지의 차수 비교표는 수작업 비교 결과와 대비해 누락 0건이어야 한다. 생성된 hwpx·xlsx는 한글·엑셀에서 열리고 담당자가 수정 없이 사용할 수 있어야 한다. |

## 4. 답변자료·국장결재 문서 자동 작성 보조 도구

| 칸 | 내용 |
|---|---|
| ① 현재 업무 | 담당자는 국회 요구자료 답변을 만들 때 정해진 답변 양식과 국장결재 양식을 사용한다. 요구번호, 의원명, 요청일자, 질의 제목, 소관 과, 답변 내용, 붙임 자료 등을 기존 hwp/hwpx 양식에 맞춰 작성한다. 같은 요구자료라도 답변용 문서와 결재용 문서를 따로 만들고, 파일명도 양식에 맞춰 저장한다. |
| ② 문제 | 답변자료와 국장결재 문서를 각각 수작업으로 만들다 보니 같은 정보가 문서마다 다르게 입력될 수 있다. 파일명 규칙, 제목, 의원명, 요청일자, 소관 과, 붙임 번호가 어긋나면 검토 과정에서 다시 수정해야 한다. 표준 양식이 있어도 담당자마다 서식과 문구가 조금씩 달라진다. PDF는 확인용이고 hwpx가 실제 작성 기준인데, 양식 버전이 섞이면 잘못된 양식으로 작성될 수 있다. |
| ③ 목표 | 접수대장과 회신 내용을 바탕으로 표준 답변자료와 국장결재 문서 초안을 자동 생성한다. 파일명, 제목, 기본 메타데이터, 소관 과, 의원명, 요청일자, 질의 제목을 같은 원천 데이터에서 채워 문서 간 불일치를 줄인다. 답변 내용은 사람이 최종 작성·확정하되, 양식 적용과 반복 입력을 자동화한다. |
| ④ 범위 | 만들 것: 답변 양식과 국장결재 양식 등록, 접수대장 메타데이터 자동 채움, 회신 내용 삽입, 파일명 규칙 적용, hwpx 산출물 생성, PDF 미리보기 또는 서식 확인, 누락 필드 표시. 만들지 않을 것: 답변 사실관계 자동 판단, 민감정보 대외 공개 결정, 국장 결재 자동 처리, 국회 제출 자동 처리. 사람이 판단할 부분: 답변 문장 최종 확정, 붙임자료 포함 여부, 비공개·개인정보 마스킹, 결재 상신 여부. |
| ⑤ 검증 기준 | 표준 답변 양식과 국장결재 양식을 기준으로 시험 문항 10건의 문서 초안을 생성한다. 생성 문서의 파일명, 의원명, 요청일자, 소관 과, 질의 제목이 접수대장 값과 100% 일치해야 한다. 필수 항목이 비어 있으면 확인필요로 표시해야 한다. 생성된 hwpx가 한글에서 열리고 표 구조와 기본 서식이 유지되어야 한다. 답변 내용의 정책적 타당성, 결재 승인 여부, 실제 제출 여부는 검증 기준에 포함하지 않는다. |

## 5. 회사 자료 수집·보안 분류·검색 지식화 도구

| 칸 | 내용 |
|---|---|
| ① 현재 업무 | 회사 업무 자료는 zip, txt, docx, hwp, hwpx, pdf, xlsx, html, exe 등 다양한 형식으로 보관되어 있다. 실제 자료 규모는 약 11GB이고 압축 파일까지 포함하면 20GB 수준까지 늘어날 수 있다. 담당자는 과거 문서, 요구자료, 과업지시서, 설치 매뉴얼, 대화 로그, 보안메일 등을 필요할 때 폴더에서 직접 찾아 열어보고, 유사 사례나 근거 문장을 찾아 업무에 재사용한다. |
| ② 문제 | 자료가 많고 형식이 다양해 필요한 파일을 찾는 데 시간이 오래 걸린다. 같은 파일이 중복 저장되어 있고, zip 안에 또 다른 자료가 들어 있어 전체 목록을 파악하기 어렵다. 대화 로그나 문서에는 API 키, 연락처, 내부망 정보, 장비 설정, 계정 정보처럼 민감할 수 있는 내용이 포함될 수 있다. 실행 파일이나 보안메일 HTML 같은 위험 파일은 열어보면 안 되지만, 단순 검색 과정에서 구분이 어렵다. 모든 문서를 한 번에 임베딩하면 비용·보안·품질 문제가 생길 수 있다. |
| ③ 목표 | 원본 파일을 안전하게 보관하면서 파일 목록, 해시, 문서 유형, 추출 텍스트, 민감정보 여부, 위험 파일 여부를 관리한다. 원본 전체를 DB에 넣지 않고, 메타데이터 DB와 검색 인덱스, 선택 임베딩 인덱스를 분리한다. 중복 파일은 해시로 식별하고, 민감정보가 포함된 문서는 마스킹·임베딩 제외·사람 확인 대상으로 분류한다. 담당자가 과거 자료를 빠르게 찾고, 안전한 범위 안에서 RAG 검색에 활용할 수 있게 한다. |
| ④ 범위 | 만들 것: 원본 보관소, 파일 목록화, 해시 기반 중복 탐지, 압축 파일 목록 확인, 문서 텍스트 추출, 민감정보 탐지, 위험 파일 분류, 검색 인덱스 생성, 선택 임베딩, 감사 로그, 사람 확인 큐. 만들지 않을 것: exe·bat·reg 실행, 보안메일 자동 열람, 모든 원본의 무차별 임베딩, 권한 없는 외부 전송, 민감자료 자동 공개. 사람이 판단할 부분: 민감정보 최종 분류, 임베딩 허용 여부, 외부 제출 가능 여부, 위험 파일 처리, 보존·폐기 기준. |
| ⑤ 검증 기준 | 시험 폴더의 파일을 대상으로 전체 파일 목록과 해시가 누락 없이 생성되어야 한다. 동일 해시 파일은 중복으로 표시되어야 한다. exe, bat, reg, 보안메일 HTML은 실행하지 않고 위험 파일로 분류해야 한다. API 키처럼 보이는 문자열, 전화번호, 이메일, 내부 시스템 정보는 민감 가능 항목으로 표시해야 한다. 검색 결과는 원본 경로와 추출 근거를 함께 보여 주어야 하며, 민감 표시된 문서는 기본적으로 임베딩 대상에서 제외되어야 한다. |
