# 디자인정의서: 국회 요구자료 대응 도우미 PoC

> 버전: `01_poc`  
> 저장 방식: 원본 CSV·XLSX·PDF는 읽기 전용, 업무 상태는 `cases.json`

## 1. 사용자와 업무 흐름

| 단계 | 국회 총괄 담당 | 현업 담당(과) | 시스템 | 사람 확인 |
|---|---|---|---|---|
| 접수 | 원문과 접수정보 확인 | - | 기본 항목 적재, 중복·기한 이상 검사 | 중복·날짜 이상 여부 |
| 분해 | 문항 단위 확정 | - | 문항 후보와 주의 문구 추출 | 예외적으로 하위 항목을 나눌지 |
| 배분 | 추천 후보 검토·확정 | 배분 결과 확인 | 후보 3순위, 근거, 확인 사유 제시 | 최종 주관·협조 과 |
| 회신 | 진행 현황 확인 | 회신 저장·완료, 재배정요청 | 상태·기한·이력 기록 | 답변의 사실관계 |
| 검사 | 누락·오류 검사 | 보완 회신 | 규칙 검사, 확인 목록 생성 | 보완요청 여부 |
| 확정 | 제출본 대상 확정 | 필요 시 최종 보완 | 미해결 확인 표시 차단 | 최종 확정 여부 |
| 제출본 | 확정 목록 확인 | - | 목록만 제공 | 결재·제출은 범위 밖 |

## 2. 상태

```text
접수 → 배분확정 → 회신중 → 회신완료 → 확정
배분확정 ← 재배정요청 ← 회신중
회신완료 ↔ 보완요청
접수 → 중복
```

`확인필요`는 상태가 아니라 표시(flag)다. 원래 진행 상태를 유지한 채 사유를 `checks[]`에 남기며, 미해결 확인 표시가 있으면 확정할 수 없다.

과거 접수대장을 S4에서 적재할 때는 다음과 같이 대응한다.

| 원본 처리상태 | 건수 | PoC 상태 | 추가 표시 |
|---|---:|---|---|
| 제출완료 | 412 | 확정 | 과거 완료 자료 |
| 보완요청 | 53 | 보완요청 | - |
| 기한연장 | 55 | 회신중 | `기한연장` |
| 앞뒤 공백이 있는 상태값 | 검증용 120건 중 1 | 공백 제거 후 위 규칙 적용 | 정규화 이력 |

교육 실습에서 처음부터 흐름을 연습할 때만 별도 옵션으로 전체 상태를 `접수`로 초기화한다. 과거 이력 적재와 교육용 초기화를 혼합하지 않는다.

| 데이터 | 용도 | 변경 |
|---|---|---|
| `요구자료_접수대장_2026국감_520건.csv` | 과거 접수·처리 이력 | 읽기만 |
| `배분기준표_소관키워드_304건.csv` | 추천 근거 | 읽기만 |

| `검증용_접수대장_120건.csv` | 검사 규칙 시험 | 읽기만 |
| `cases.json` | 문항별 상태·담당·회신·검사·이력 | 읽기/쓰기 |

`cases.json` 핵심 구조:

```json
{
  "caseId": "2026-0001-01",
  "receiptNo": "2026-0001",
  "questionNo": "1",
  "status": "접수",
  "leadDept": null,
  "supportDepts": [],
  "replyDueAt": null,
  "objectionDueAt": null,
  "flags": [],
  "checks": [],
  "history": []
}
```

기한은 다음 규칙으로 계산한다.

| 항목 | 계산 | 표시·처리 |
|---|---|---|
| 회신기한 | `배분일시 + 3일`과 의원실 제출기한 중 빠른 시각 | 경과 문항을 현황에 표시 |
| 이의기한 | 배분 통보 시각 + 2시간 | 경과 후 재배정요청에 `기한경과` 표시, 수용 여부는 총괄 판단 |
| 미회신 공지 | 매일 10시 기준 미회신 과 | 공지문 초안만 제공, 발송은 사람이 수행 |

## 5. 추천과 검사

추천 점수는 업무 지침을 대체하지 않는다. 기준표 키워드, 요구내용 앞부분의 주제어, 제외어, 조직도 주요업무, 공통 문항 여부를 합쳐 후보 순서를 만들고 담당자가 확정한다. 내부 40건에서 나온 40/40은 산식 개발 자료의 결과로만 기록한다.

| 검사 | 처리 |
|---|---|
| 조직도 26개 과 밖 부서명 | 확인 표시 |
| 요구기간 시작일 > 종료일 | 확인 표시 |
| 같은 접수번호 중복 | 먼저 접수된 건 유지, 담당자 확인 후 `중복` |
| 배분과·요구내용 공란 | 확인 표시 |
| 제출기한 < 접수일 | 의원실 확인 대상 표시 |
| 상태값·셀 앞뒤 공백 | 정규화 후보와 변경 이력 기록 |
| 금액 단위가 천원이 아님 | 확인 표시 |
| 집행액 > 예산인데 비고 공란 | 보완요청 후보 |
| 요구기간 연도 행 누락 | 보완요청 후보 |
| 회신 양식 열 변경·합계 불일치 | 보완 또는 확인 대상 |

회신 샘플 6개에는 측정 가능한 의도 오류가 3건 있다. 지역정책과의 2023년 행 누락 1건, 안전정책과의 집행액 초과·비고 공란 1건, 산업정책과의 합계 불일치 1건을 모두 검출해야 한다.

## 6. `/api/app`

조회는 GET, 상태를 바꾸는 작업은 POST 한 곳으로 시작한다.

```http
GET /api/app?view=dashboard&role=총괄
```

```json
{
  "ok": true,
  "view": "dashboard",
  "summary": {"total": 520}
}
```

지원 작업: `접수`, `AI추천`, `배분`, `회신`, `재배정요청`, `보완요청`, `확정`.

```json
{
  "action": "AI추천",
  "actor": "국회 총괄 담당",
  "payload": {"caseId": "2026-0001-01"}
}
```

```json
{
  "ok": true,
  "caseId": "2026-0001-01",
  "candidates": [
    {"rank": 1, "dept": "운영지원과", "score": 82, "evidence": ["업무추진비", "공통 취합 기준"]}
  ],
  "needsHumanReview": true
}
```

모든 POST는 `actor`, `action`, `reason`, 변경 전·후 값, 시각을 이력에 남긴다.
